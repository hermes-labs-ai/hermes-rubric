# Evaluation coverage

This file separates release evidence from claims that still need a dedicated study.

## Mechanically covered

- public in-memory, path, and async transaction contracts;
- caller-provided, class-template, and synthesized rubric mode validation;
- complete/partial coverage reporting and UTF-8 byte safety;
- directory source-limit disclosure;
- normalized stage errors with chained causes;
- quality, evidence, and coverage feedback separation;
- existing hedge, no-evidence, source-authority, citation, batch, backend, and adversarial behavior;
- package version, build contents, clean-wheel imports, and CLI surfaces at release time.

These checks license bounded compatibility and packaging claims for the exact reviewed release. They do not establish general assessment accuracy.

## Existing bounded evidence

The committed batch-equivalence report documents agreement between batched and per-dimension execution on its frozen fixtures. Its own limitations govern the claim; it is not a human-validity or “better than raw judge” result.

## Still unproven

- agreement with adjudicated human labels across domains;
- superiority to raw LLM judging or framework-native evaluators;
- full-document recall beyond the v1.1 prefix strategy;
- cross-runtime equivalence through official adapters;
- calibration, compliance, or autonomous-release fitness.

Public positioning should therefore stay concrete: cited evidence, scoring clamps, uncertainty, coverage reporting, portable integration, and receipts.
